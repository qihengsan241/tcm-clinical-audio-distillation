# 中医跟诊录音整理 Skill

`tcm-clinical-audio-distillation` 是一个面向中医跟诊、师承讲课和病例讨论录音的 Codex Skill。它把长录音整理成可回听、可核验、可持续积累的学习资料，并重点保存老师的临床推理，而不只生成一篇摘要。

## 它解决什么问题

跟诊时常同时出现患者叙述、老师问诊、辨证、方药、教学讲解和个人经验。普通摘要容易丢掉三类最重要的信息：

- 老师为什么要问这个问题；
- 老师为什么选择这个方、这些药及这个力度；
- 用药后准备观察什么，以验证原来的判断。

本 Skill 将这些内容拆成有关联的数据对象，同时严格区分老师原话、患者事实、AI解释和听写存疑内容。

## 主要能力

- 判断录音属于病例主导、教学主导还是混合材料；
- 整理完整病例与不完整病例片段；
- 保存“提出原则 → 举例 → 连接病机 → 解释用药力度 → 指出误区 → 验证”的教学过程；
- 建立可跨病例积累的老师经验 Wiki；
- 还原问诊目的、辨证证据、治法和方药理由；
- 区分实际开方、旧方回顾、条件性举例和教学讨论；
- 对方名、药名、剂量和否定词建立逐项置信度与待核对任务；
- 允许AI补充医理，但要求列出依据、缺失信息和验证方法；
- 标记儿童、孕产妇、急症、高风险剂量及中西药相互作用等安全边界；
- 默认去除姓名、电话、住址等直接身份信息。

## 输出结构

一次整理通常包含：

1. 录音内容地图；
2. 老师的教学方法；
3. 病例及问诊路径；
4. 辨证、治法与方药推理；
5. 老师个人经验 Wiki；
6. 随访与疗效验证；
7. AI医理解释；
8. 需要回听或向老师核对的问题。

完整字段见 [数据架构](references/schema.md)，成稿格式见 [输出模板](references/output-template.md)。

## 方药记录规则

只要录音出现方药，就必须记录它在当前语境中的角色：

| 角色 | 含义 |
|---|---|
| 实际开具 | 老师在本次或所述诊疗中真实使用 |
| 旧方回顾 | 回顾此前给患者使用的处方 |
| 条件性举例 | 说明“某种情况下可考虑某方” |
| 教学讨论 | 讲解方义、配伍或经典条文 |
| 无法判断 | 录音不足以确认是否真实开方 |

病例中的方药还应回答：为什么选这个方、关键药物对应什么证据、为什么这样加减或决定力度，以及准备观察哪些变化。如果老师没有说明原因，输出应明确写“录音未说明完整选方理由”，不能用教材知识冒充老师当时的推理。

## 安装

将本仓库目录复制到 Codex Skills 目录。例如：

```text
C:\AI\Shared\Skills\tcm-clinical-audio-distillation
```

也可以放入当前环境的个人 Skills 目录。确保目录中直接包含 `SKILL.md`。

## 使用

显式调用：

```text
使用 $tcm-clinical-audio-distillation 整理这份中医跟诊录音。
```

也可以直接提出自然语言请求：

```text
整理这份师承录音，提取病例、老师经验，以及每个方药的使用理由。
```

输入可以是音频、带时间戳的转写稿或人工记录。若输入为音频，具体语音识别工具可按本机环境选择；Skill 不绑定某一家云端服务。

## 云端运行

仓库已经包含 Codex Cloud 项目级入口、`gpt-transcribe` 音频转写脚本、Hosted Skill 打包脚本和 GitHub Actions 校验。云端模式会先把大录音压缩并按 8 分钟分片，再逐段转写；原始音频和逐字稿只留在私有工作目录。

完整配置、运行和发布方法见 [CLOUD.md](CLOUD.md)。云端环境需要一次性配置 `OPENAI_API_KEY` Secret；不得把 Key、患者录音或原始转写提交到 GitHub。

## 隐私与临床边界

本仓库不应存放真实患者的音频、逐字稿、姓名、联系方式、住址、证件信息或可识别的就诊信息。`.gitignore` 已排除常见音频和转写文件，但提交前仍应人工检查。

本项目用于整理学习资料和保存临床推理，不替代四诊、检查、处方审核、急症评估或当地医疗规范。老师的个案经验应保留来源、适用条件和边界，不能自动转化为通用处方或剂量规则。
